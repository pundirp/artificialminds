Feeding an AI Agent the Facts

A bakery’s flour is late again! Its supplier, All You Knead, has a new AI agent answering customers, and the agent keeps getting the facts wrong. What does it take to give an agent the right facts for a real job?

Both facts in this draft are made up.

  1. “Your order is on the truck and will reach you by 10:00 tomorrow.”

  2. “As a valued customer, you qualify for our standard 10% late-delivery credit.”

    All You Knead has no standard 10% credit for late deliveries. The agent had no credit policy to read, so it made up a figure that sounds normal.

Chapter 1

Context window: the model writes from the text it is given

The first reply is polite and clear, and both of its facts about Madeleine’s order are made up.

ToolA tool is a program that the agent’s software runs at the model’s request. The software passes the result back to the model as text.Parametric memoryParametric memory is what a model holds in its weights, the numbers set in training.

An agent has three parts: the model, the agent’s software and the tools. The model is trained on a large body of public text, and it writes new text one word at a time. The agent’s software sends the model its instructions. The tools are programs that the software runs for the model, such as a search of the company’s records.

A model’s facts sit in two places. The first is its weights, a long list of numbers set in training. The facts in the weights are the model’s parametric memory. The training text ends at a cutoff date, and after training the weights stay fixed.2,3 The weights hold no facts from All You Knead’s records.

Fixed weightsThe padlock in the drawing shows that a model’s weights stay fixed after training. The model can still use new facts that the software places in its context window with each request.

The weights hold more of the facts and passages that appear many times in the training text.10,11

Context windowThe context window holds all the text a model reads to write an answer. That text is the context. The window has a fixed size, counted in tokens.TokenA token is a word or a piece of a word.Fine-tuningFine-tuning is a short extra round of training on new text. It changes a model’s weights.

The second place is the context window. It holds the text the model reads with each request. That text includes the instructions, Madeleine’s email and anything else the software adds. All of that text together is the context. The window has a fixed size, measured in tokens. A token is a word or a piece of a word.12

A team can also add its own text to the weights with fine-tuning, a short extra round of training. All You Knead’s tech team skipped fine-tuning. With each fix, the team puts facts into the context window, and the weights stay as they are.

Why the model made up the facts

For the first reply, the context window held the instructions and Madeleine’s email, and no company records. In the text the model trained on, replies to complaints about late deliveries often include a credit. So the model added a round 10% credit, and it made up a delivery time in the same way.

HallucinationA hallucination is a false statement from a model. The statement reads like a true one.

The model writes an invented fact the same way it writes a true one. Such a fact is a hallucination. In 2025, Kalai and colleagues traced hallucinations to the way people train and test models. Most tests, and the training aimed at them, give a confident guess more points than “I am not sure.”13

All You Knead’s shared drive holds about 40,000 documents. That is 300 times as much text as the context window holds. So for each reply, the agent’s software has to find the few facts that matter and copy them into the context window.

A closer look

Fine-tuning, and why the team skipped it

Fine-tuning could put All You Knead’s contracts into the weights. For All You Knead, it has three problems. A fact in the weights comes with no source, so Dusty could not check a credit against the contract. The weights stay the same until the next round of training, so a new contract would have to wait. And every user gets the same weights, so the model could write All You Knead’s private margin on the bakery’s orders into a reply for any user.

In 2023, Ovadia and colleagues compared fine-tuning with retrieval, in which software copies the facts into the context window. They tested three models on two kinds of question: school subjects from the models’ training text, and news from after the models’ cutoff dates. The models scored higher with retrieval on both kinds of question.14

TableA table is a grid of information in a database. Each column holds one kind of fact, such as a date.RowA row is one record in a table, such as one order.JoinA join matches rows from two tables through a column they share.SQLSQL, short for structured query language, is a language for asking a database for rows.Text-to-SQLIn text-to-SQL, a model writes a SQL query from a question in plain words.

To find Madeleine’s order, the agent has to read All You Knead’s tables. A table is a grid, like a spreadsheet. Each row holds one record, such as one shipment. The company keeps its records in three systems. Sales records sit in the customer relationship management system, or CRM. Finance records sit in the enterprise resource planning system, or ERP. Warehouse records sit in the warehouse management system, or WMS. Each system has its own tables.

The bakery’s customer number, Bakery-2, sits in the CRM’s column acct_id and in the ERP’s column cust_ref. A column of ID numbers like these is a key. Matching rows from two tables through a shared key is a join. Software gets rows from a database with SQL, a language for database queries.

First, the team connected the agent to these tables. The agent turned Madeleine’s email into a SQL query. This step is text-to-SQL. The query found her shipment. In the shipment’s row, the flag in the column dly_flg was off. The agent could read the flag as “not delayed” and write that the order is on time.

dly_flg is short for “delay flag”, and the warehouse sets the flag when a shipment leaves the dock late. Madeleine’s order left the dock on time, so the flag stayed off. The flag carries no information about when the order reaches her.

The staff learned on the job what each code stands for, and the meanings were not written anywhere. So the agent could not look a code up.

What an ontology holds

OntologyAn ontology is a written description of a business. It lists the kinds of things the business deals with, their properties, the links between them and the rules about them.PropertyA property is one kind of fact that a company keeps about a thing, such as a shipment’s status.

An ontology is a written description of a business. It lists the kinds of things the company deals with, such as customers, orders and shipments. It also lists the links between them. Each kind of thing has properties, such as a shipment’s agreed delivery time.

All You Knead’s engineers wrote an ontology for the company and connected it to the tables. They wrote down where each property’s data sits and listed matching columns, such as cust_ref and acct_id (Figure 4). The agent then writes its requests with plain names, such as “agreed delivery time”, and the software finds the right tables and joins them.

RuleA rule is a definition that a company writes down once, such as the way to measure a shipment’s lateness. Every query then uses the same definition.

The engineers also wrote the company’s rules into the ontology, such as its rule for lateness. Under that rule, the software counts the hours between the agreed delivery time and the shipment’s arrival. If the shipment is still on the road, the software counts up to the current time. The agreed delivery time is the end of the customer’s delivery window on the promised date in the order’s record. The bakery’s window ends at 7:00 in the morning.

With the ontology, the agent found Madeleine’s order at a depot of Northline Freight, the delivery company. The order was due before 7:00 on Saturday, so by Tuesday morning it was more than 72 hours late. Both facts can now go into the reply.

Real-world case

An ontology in an insurance test

In 2023, researchers at data.world asked GPT-4 questions about insurance data. With the list of tables and columns, GPT-4’s queries returned the right answer about 17% of the time. With an ontology of the same business, they were right about 54% of the time.15

Palantir and Microsoft both sell software built on an ontology. Microsoft’s version is Fabric IQ.16,17

The ontology still has two gaps. The company’s goodwill rule gives customers a free delivery if their revenue exceeds $55,000 over 12 months. But the engineers never specified which definition of revenue to use. The ontology also has no link between the bakery’s old warehouse account, Bakery-1, and its current account, Bakery-2.

A closer look

Schemas, taxonomies, OWL and RDF

In 1993 the computer scientist Tom Gruber wrote: “An ontology is an explicit specification of a conceptualization.”18 Two older ideas overlap with an ontology: the schema and the taxonomy. A schema is the list of tables and columns in one database. A taxonomy is a set of categories inside categories, such as Food, then Flour, then Rye flour. An ontology holds categories too, along with properties, links and rules.

The W3C, the group that sets standards for the web, publishes formats for writing ontologies as data. One of these formats is RDF. In RDF, each fact is a triple of a subject, a predicate and an object, such as “Madeleine’s Bakery places an order”.19 RDF Schema and OWL add ways to describe kinds of things and their properties. Each kind of thing is a class. The W3C calls OWL 2 “an ontology language for the Semantic Web with formally defined meaning”.20,21 The data.world team wrote its insurance ontology in OWL.15

A semantic layer is software that holds a written definition for each of a company’s terms and numbers, such as revenue or an active customer. Each definition comes with a formula and the tables that hold its data. The company’s reports and its agent get their numbers from the same definitions, so the numbers match.

MetricA metric is a number that a company tracks, such as net revenue.DimensionA dimension is a way to split a metric, such as by region or by month.

Each number in the layer is a metric, with one agreed name and one formula. The layer also lists dimensions, the ways to split each metric, such as by region or by month. To get a number, the agent sends the layer the name of a metric and a dimension. The layer writes the SQL query, runs it and returns the result.

All You Knead’s goodwill policy uses net revenue, the money on the invoices minus refunds. With the semantic layer, the agent gets the bakery’s net revenue. That figure is below the $55,000 cutoff, so the agent leaves the free delivery out of its reply.

A closer look

Two kinds of revenue, and the one the goodwill rule uses

To apply the goodwill rule from Chapter 2, the agent needs the bakery’s revenue over the last 12 months. The company counts revenue in two ways. Without the semantic layer, nothing the agent reads shows which one the rule uses. The sales team counts bookings, the value of every order a customer has placed, including orders with no invoice yet. The bakery’s bookings come to more than $55,000. If the agent uses that total, it offers Madeleine a free delivery.

The finance team counts net revenue, the money on the invoices minus refunds. The goodwill policy uses net revenue, and the bakery’s net revenue is below $55,000.

Across the whole company, finance reports revenue of about $4.1 million for July to September 2025, and sales reports about $4.6 million. Each team’s math is correct, and both teams call the result “revenue”.

In the semantic layer, finance’s revenue is the metric “net revenue”, and sales’ revenue is the metric “bookings”. The engineers then rewrote the goodwill rule to use net revenue.

In August 2026, Tristan Handy, a co-founder of the software company dbt Labs, spoke about numbers with no stored definition. For those, an agent has to rebuild the definition for each question: “AI agents have to try to re-derive that for themselves at every turn.”22

In September 2025, Snowflake, Salesforce, dbt Labs and other companies started the Open Semantic Interchange, a project to build a shared, open format for metric definitions.23 In June 2026 the project moved to the Apache Software Foundation, a nonprofit that looks after free software, under the new name Apache Ossie.24,25

Under clause 4.2 of its contract, the bakery gets a credit of 5% of an order’s value when a delivery is more than 48 hours late. The contract is a PDF, one of about 40,000 documents on the shared drive. With no way to search them, the agent would make up a credit, as it did in the first draft.

RAGRAG is short for retrieval-augmented generation. A search finds chunks and puts them into the context, and the model writes its answer from them.ChunkA chunk is a short piece of a document, usually a few hundred tokens long. Cutting documents into chunks is chunking.EmbeddingAn embedding, or vector, is a list of numbers that an AI model makes from a chunk. Chunks with similar meanings get similar numbers.

The fix is retrieval-augmented generation, or RAG. The name comes from a 2020 paper by Patrick Lewis and colleagues.26 For each request, a search finds the few pieces of the documents that best match the agent’s search words. The software copies them into the context. The model then writes its reply from them.

The team prepares the documents once, ahead of time. Software pulls the text out of every file and cuts it into chunks. This step is chunking.27 If the chunks are too small, “more than 48 hours” can land in one chunk and “5%” in the next. A search could then return half of the rule. Next, an embedding model turns each chunk into a list of numbers, called an embedding or a vector. Chunks with similar meanings get similar numbers. The software stores the chunks and their vectors in an index, a database built for search.

Vector searchVector search, also called semantic search, turns the query into a vector and finds the chunks whose vectors are closest to it.

To find a fact, the agent writes a search query, a few words such as “late delivery credit”. The embedding model turns the query into a vector as well. A vector search then gives each chunk a score for how close its vector is to the query’s vector.28 The best three go into the context, each with a tag for its file and page. The model cites the tag for each fact.

Keyword search and vector search

Keyword searchKeyword search finds the chunks that contain the words in the query. It then ranks them with a score.Hybrid searchHybrid search runs a keyword search and a vector search and merges their two ranked lists.

A vector search can find a chunk with the same meaning as the query, even when the chunk uses other words. Keyword search finds chunks with the query’s exact words and codes, such as the contract number “MB-2025”.29 Each search ranks its results, best match first. Hybrid search runs both searches and merges the two ranked lists into one.30

Added context and filters

For Madeleine’s request, the agent searches for “late delivery credit”. The first row of Figure 7 shows that search over a small set of chunks. Every kind of search ranks Corner Deli’s clause first. Corner Deli is another customer, with a smaller credit. The customer’s name sits on page 1 of each contract, so a chunk from page 4 does not show whose contract it is. If the model wrote its reply from Corner Deli’s clause, Madeleine would get another customer’s terms.

Contextual retrievalIn contextual retrieval, a model writes a short note for each chunk before the chunk goes into the indexes. The note holds facts from the rest of the document, such as the customer’s name.RerankerA reranker is a second model that reads the search query and one chunk from the search together. It gives that chunk a new score.

In September 2024, Anthropic described a method called contextual retrieval. Before the chunks are stored, an AI model reads each whole contract. It then writes a short note at the front of each chunk, with facts such as the customer’s name. Each chunk then shows whose contract it comes from. Anthropic tested the notes together with keyword search and a reranker, another AI model that gives the top chunks new scores. The three fixes together cut the number of missed chunks by about two thirds.27

MetadataMetadata is the set of facts stored beside a chunk, such as its customer and the dates its contract is in force.FilterA filter is a rule about metadata. The software removes every chunk that breaks the rule. Then the search ranks the rest.

The team also stores a few facts beside each chunk, called metadata. They include the chunk’s customer and the start and end dates of its contract. Before ranking, the software filters the chunks by their metadata.31 One filter keeps the bakery’s chunks, and another keeps current contracts. Together the two filters remove Corner Deli’s clause and the clause from the bakery’s expired 2024 contract.

With these fixes, the top chunk is clause 4.2 of the bakery’s current contract. Madeleine’s order is more than 72 hours late, so the clause applies. Once the order arrives, she gets a credit of 5%, or $109.

RAG makes the answers more accurate, and teams are still working on improving it.

Real-world case

Legal research tools built on RAG

In 2024, Magesh and colleagues at Stanford and Yale tested three legal research tools built on RAG. Between 17% and 33% of the tools’ answers were false or cited a source that failed to back them up. For GPT-4 with no search, the figure was 43%.32

A knowledge graph links records of many kinds, such as customers, orders, shipments and products. An agent can then follow the links from one record to another. For Madeleine’s reply, the agent needs every record about her bakery.

Madeleine wrote that this is the third late delivery since September. Without a knowledge graph, the agent finds one late delivery, the current one. The agent then writes that this delivery is the first. The two late deliveries in September sit under the bakery’s old account number, Bakery-1. In January 2025 the company gave the bakery a new number, Bakery-2. The warehouse system kept the old number until October, so a search for Bakery-2 misses both September deliveries.

Entity resolutionIn entity resolution, a program finds and links the records in different systems that are about the same customer or thing.Knowledge graphA knowledge graph stores each record as a node and links the nodes with named edges.Node and edgeA node is one record, such as a customer or an order. An edge is a link between two nodes, and it has a name, such as “placed”.

All You Knead’s systems hold three records for this one customer. The CRM stores it as “Madeleine’s Bakery”, the invoices as “MADELEINES BKRY LLC”, and the warehouse’s September records as Bakery-1. A program can compare records like these and link the ones that belong to the same customer. It checks clues such as a shared address, a shared tax ID and the CRM’s entry for the change from Bakery-1 to Bakery-2. Finding and linking these records is entity resolution.

The team stores the linked records in a knowledge graph. Each record becomes a node. Each link between two records becomes an edge, and every edge has a name, such as “placed” or “same as”. The ontology from Chapter 2 lists the kinds of records, such as Customer and Order, and the graph holds the real records of each kind.

Real-world case

Google’s Knowledge Graph

Google launched its Knowledge Graph for web search in May 2012, with a blog post titled “Introducing the Knowledge Graph: things, not strings”.33 A string is a programmer’s word for a piece of text. Google’s graph held records for the things behind the words in a search, such as people and places.

Paths through the graph

Multi-hopA multi-hop question takes several steps along the edges of a graph to answer. Each step is one hop.

To list the bakery’s late deliveries since September, the agent starts at the bakery’s node and follows its edges. One path leads to the current order and its shipment. A second path crosses the “same as” edge to the old account and reaches the two September shipments. Each step along an edge is a hop, so a question like this one is a multi-hop question.

With the graph, the agent finds all three late deliveries. It can now write “This is the third late delivery since September.”

Entity linkingIn entity linking, a program finds a name in a piece of text, such as “Madeleine’s Bakery”, and links the name to the matching record.

A program can also link documents to the graph. It finds a name such as “Madeleine’s Bakery” in a contract or a note and links that document to the node with the same name. This step is entity linking.

A closer look

GraphRAG builds a graph from the text of documents

Darren Edge and colleagues at Microsoft Research described GraphRAG in a 2024 paper. A language model reads a whole collection of documents. It lists the entities in the documents, such as people and companies, and the links between the entities.

A program sorts closely linked entities into groups, and the model writes a summary of each group. For a question, the model writes a partial answer from each summary and then combines the partial answers into one. The authors built GraphRAG for questions about a whole collection, such as “What are the main themes in the dataset?”34

Writing every summary ahead of time costs a lot. Microsoft’s cheaper LazyGraphRAG, announced in November 2024, writes no summaries ahead of time. It uses a model after a question arrives. Microsoft reported that LazyGraphRAG’s setup costs the same as plain vector RAG and 0.1% of the cost of full GraphRAG.35

As of October 2026, Microsoft lists GraphRAG as largely in maintenance mode, with no new features planned.36

Context rotContext rot is the drop in a model’s accuracy as the text in its context grows longer.DistractorA distractor is a piece of text on the same topic as the question. It holds no answer to the question.

The agent can now reach tables, the semantic layer, documents and the knowledge graph. In the team’s first design, the software fetched everything that the graph links to the bakery and pasted it all into the context. That filled most of the context window. The pile included an old status row for one of the September shipments, with a delivery date in late September. No one had ever closed the row, so it still looked current. With that row in its context, the model could copy the old date into the reply. Madeleine would then read a promised delivery date nearly four weeks in the past.

A model’s answers become less accurate when its input is long or includes distractors. A distractor is text on the right topic that holds none of the needed facts. The old status row was a distractor. The row was about a late delivery to the bakery. It held no facts about Madeleine’s current order.

Real-world case

Lost in the middle, and context rot

In 2023, Nelson Liu and colleagues found that models often miss a fact in the middle of a long input.37 In 2025, the search company Chroma tested 18 models. All 18 did worse as the input grew longer, and even one added distractor lowered the scores. Chroma titled its report Context Rot.38

Workflows and agents

WorkflowA workflow is a design in which developers write every possible path in code ahead of time.Tool callA tool call is a request from the model to run one tool with certain inputs, such as a shipment number.Context engineeringContext engineering is the work of choosing what goes into a model’s context at each step.

In December 2024, Anthropic described two ways to build a system around a model. In a workflow, developers write every possible path in code ahead of time. In a simple workflow, such as the paste-everything design, the path is deterministic: the same steps run in the same order every time. The model’s words can still differ from one run to the next. In an agent, the model requests each next step itself.39

So the team rebuilt the agent to work in a loop. The model requests one tool call at a time and reads the result before it requests the next. For Madeleine’s email, the model requests the newest status row of her shipment, so the old September row stays out of the context. The model can now give Northline’s current estimate: before 7:00 on Wednesday.

In June 2025, Andrej Karpathy, a founding member of OpenAI, described context engineering in a post on X.

Context engineering is the delicate art and science of filling the context window with just the right information for the next step.

Andrej Karpathy, post on X, 25 June 2025.40

Agentic retrievalAgentic retrieval is document search that the model requests as one of the agent’s tools. The model writes the search words, reads the results, and can search again with better words.

In Chapter 4, the search runs once, before the model writes its reply. Now document search is one of the agent’s tools. The model writes the search words, reads the results, and can search again with better words. Search that the model requests in this way is called agentic retrieval.

Real-world case

The claim that RAG is dead

Each time a new model comes out with a bigger context window, people on social media declare that RAG is dead.41

Some people make the same claim about coding agents. In May 2025, Hamel Husain and Shreya Shankar answered a widely shared article, “Why I No Longer Recommend RAG for Autonomous Coding Agents”. They wrote that its author argued against one simple method for coding agents: a plain search of a vector database.42

Boris Cherny created Claude Code, Anthropic’s coding agent.43 On 1 February 2026 he posted: “Early versions of Claude Code used RAG + a local vector db, but we found pretty quickly that agentic search generally works better.”44

Anthropic’s engineers wrote that Claude Code finds files during a task with glob and grep, two simple search commands.45 Grep finds the lines that contain a given word. Glob lists the files whose names match a pattern. Code is full of exact names, such as the names of files and functions, so these two commands work well on code.

The words in a contract often differ from the words in the question. A vector search can still find the clause. So All You Knead’s team kept the document search from Chapter 4 as one of the agent’s tools.

MCP connects AI apps to tools

MCPMCP, the Model Context Protocol, is a shared format for connecting tools to AI apps. A system with an MCP server works with every app that supports MCP.

With MCP, a system’s team builds one MCP server, and every AI app that supports MCP can use its tools. MCP, the Model Context Protocol, is a shared format for connecting tools to AI apps. An MCP server is a program that gives AI apps a system’s tools in that format. Anthropic released MCP in November 2024.46 OpenAI added MCP to its Agents SDK, a software kit for building agents, in March 2025.47 In December 2025, Anthropic gave MCP to the Agentic AI Foundation, part of the Linux Foundation.48 By July 2026, MCP’s main software kits were downloaded close to half a billion times a month.49

IntegrationAn integration is a piece of code that links one system’s tools to one AI app.

Before MCP, most AI apps had their own format for tools, so a team that wanted its system in several apps wrote one integration for each app. An integration is a piece of code that links one system’s tools to one AI app. In March 2023, for example, OpenAI launched plugins for ChatGPT. Each plugin held a description of its abilities in a file laid out in OpenAI’s own format.50 Anthropic wrote that each new data source needed its own custom code, and called the result “fragmented integrations”.46

Some of the agent’s tools reach the warehouse system, the finance system and document search. All You Knead’s staff also use AI apps from other makers, such as a chat assistant in the office software and a coding tool. The staff want those apps to reach the same systems. Without MCP, three apps and three systems take 3 × 3 = 9 integrations. With MCP, they take 3 + 3 = 6 pieces of work. Each system’s team builds one MCP server, and each app’s maker adds MCP to the app once.

An app that supports MCP gets the tools from each MCP server and sends the model’s tool calls to that MCP server. Inside the app, one MCP client holds the connection to each MCP server.51 All You Knead’s agent, for example, holds three MCP clients, one for each system’s MCP server. When the app connects, each MCP client fetches the list of tools from its MCP server. Each tool comes with a name, a description in plain words and the inputs it takes, such as a shipment number.52 Most apps copy the list into the model’s context.51 The model then writes a tool call, and the app sends the call to the MCP server. The MCP server runs the call and sends back the result.52

MCP has two costs: the tool descriptions take room in the context, and a description can carry hidden instructions. An agent linked to thousands of tools reads hundreds of thousands of tokens before it reaches the request.53 Apps linked to many MCP servers can load the descriptions a few at a time.51 Anthropic gave an example in which an agent writes code to call its tools. That agent used 2,000 tokens for a task that took 150,000 tokens the usual way.53

A tool’s description can also hold instructions that the model reads and the user never sees. Hiding instructions this way is tool poisoning. Invariant Labs showed this attack in April 2025.54 Chapter 7 shows a similar attack, hidden in an email (Figure 12).

A closer look

Why use MCP when an agent can already call an API?

An agent can call an API directly. Someone still has to write code for it. That code turns the API into tools for the model. With MCP, the system’s own team writes that code once, as an MCP server. Every AI app that supports MCP can then use it.55

An API is the set of requests that one program accepts from another.56 To give an agent tools for All You Knead’s warehouse API, a developer writes a name and a plain description for each tool. The developer also writes the shape of each tool’s inputs, the sign-in and the code that calls the API. Without MCP, someone writes a copy of that code for each AI app, in that app’s own format.

When the warehouse team adds a tool to its MCP server, every app gets the new tool on its next fetch of the list of tools. An MCP server can also send a notice when its list changes.52

For MCP servers reached over the web that need a sign-in, the specification holds one method, based on OAuth 2.1.57 Sign-in is optional, and a local MCP server takes its credentials from the computer it runs on.57 Under the specification, apps should show the user each tool call and give the user a way to turn it down.52

MCP adds a layer. In the warehouse case, the MCP server calls the same API underneath. For one app that calls one API, code written straight against the API is simpler.

A. Twelve RAG methods

Researchers and companies have published many methods that change one or two steps of RAG. The first step happens once, ahead of time: software prepares the documents. It cuts them into chunks and stores the chunks in a search index. The other steps happen for each request. The agent writes a search query. Software searches the index, ranks the chunks it finds and fills the context with the best of them. The model then writes the reply. A last step, checking the reply, comes in Chapter 8. WorkflowA workflow is a design in which developers write every possible path in code ahead of time.

C. Further reading

  1. Patrick Lewis and colleagues, “Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks” (2020). The authors of this paper gave RAG its name. In the first pages, they describe the method from Chapter 4: search the documents first, then write the answer.
  2. Anthropic, “Introducing Contextual Retrieval” (2024). Anthropic’s engineers add a line of context to every chunk, and then they measure how often the search still misses the right chunk.
  3. Juan Sequeda, Dean Allemang and Bryon Jacob, “A Benchmark to Understand the Role of Knowledge Graphs on Large Language Model’s Accuracy for Question Answering on Enterprise SQL Databases” (2023). The authors ask GPT-4 the same questions about raw database tables and about a knowledge graph of the same data. GPT-4 gets far more answers right with the knowledge graph.
  4. Darren Edge and colleagues, “From Local to Global: A Graph RAG Approach to Query-Focused Summarization” (2024). Researchers at Microsoft build a graph from a large set of documents and use it to answer questions about the whole set.
  5. Kelly Hong, Anton Troynikov and Jeff Huber, “Context Rot” (2025). Researchers at Chroma test 18 models and find that the answers get less reliable with longer input.
  6. Anthropic, “Effective context engineering for AI agents” (2025). Anthropic’s engineers explain how they choose the contents of a model’s context.
  7. Hamel Husain and Shreya Shankar, “AI Evals: Everything You Need to Know” (2025 to 2026). Husain and Shankar answer common questions about testing AI systems, such as how to test the search and the written answer separately.
  8. Simon Willison, “The lethal trifecta for AI agents” (2025). In a short post, Willison lists three abilities that put an agent at risk: access to private data, exposure to untrusted content and a way to send data out. When an agent has all three, an attacker can use hidden instructions to steal the private data.
  9. Pundir, three more pieces on Artificial Minds (2026). “A Talking Machine of Your Own” shows how training sets a model’s weights and freezes them. “Who Learns Faster, a Toddler or a Chatbot?” shows that a model learns slowly in its weights and quickly from examples in its context. The piece ends on continual learning, the open question of whether agents can learn on the job like a new employee. The murder mystery in “Who Killed Aldous Finch? A Transformer Explainer” shows how a model looks back at every earlier word to write the next one.
